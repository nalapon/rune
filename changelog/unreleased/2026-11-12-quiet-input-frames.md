- **Windows: input that changes nothing presents nothing on a resting window.** A frame a timer asked for on a resting window was built before taking a drawable and dropped when it drew what was on screen; a frame input asked for always drew and presented, so moving the pointer over content that doesn't hover rendered and presented up to once a refresh. Input frames take the same path once the last frame has left the drawable queue (100 ms after its present); sooner, they acquire first as before, so a drawable wait doesn't age them. On Windows a steady run's frames still present.
